** Fix stale =LIBRARY_PATH= from the emacs-plus bundle

=emacs-plus= bakes a =LIBRARY_PATH= into =Emacs.app/Contents/Info.plist=
(=LSEnvironment=) at build time so native-comp can link. It hard-codes the
Homebrew Cellar path of whatever gcc was installed then, e.g.
=/opt/homebrew/Cellar/gcc/15.2.0_1/lib/gcc/current/gcc/aarch64-apple-darwin24/15=.
Upgrading gcc deletes that directory, and since every process spawned from
Emacs inherits the variable, =ld= then warns on every compile:
=ld: warning: search path '...' not found=.

Recompute it from the =current= symlink instead, so a gcc upgrade cannot rot
it again. Runs early, before native-comp links anything.

#+begin_src emacs-lisp
(when (eq system-type 'darwin)
  (let* ((versioned (car (last (file-expand-wildcards
                                "/opt/homebrew/lib/gcc/current/gcc/*/[0-9]*"))))
         (dirs (seq-filter #'file-directory-p
                           (delq nil (list versioned
                                           "/opt/homebrew/lib/gcc/current"
                                           "/opt/homebrew/lib")))))
    (when dirs
      (setenv "LIBRARY_PATH" (string-join dirs ":")))))
#+end_src

** Let project.el use projectile's roots

=project.el= (built-in) and projectile are separate systems. Tools that
call =project-root= — like the claude-code-ide Emacs MCP =project-info= —
only see projects that =project.el= detects. Bridge the two so any project
projectile knows about is also a =project.el= project.

We return a =transient= project rooted at projectile's root. Unlike the
VCS backend this lists *all* files under the root, tracked or not, which
is what we want.

#+begin_src emacs-lisp
(defun my/project-projectile (dir)
  "Return a transient project rooted at projectile's root for DIR, else nil.
Used as a `project-find-functions' entry so `project.el' (and anything
built on it) recognizes projectile projects."
  (when (fboundp 'projectile-project-root)
    (let ((root (projectile-project-root dir)))
      (when root
        (cons 'transient root)))))

(with-eval-after-load 'project
  ;; Append (t) so the built-in VCS backend gets first crack; projectile
  ;; only fills in for directories git/hg don't already claim.
  (add-to-list 'project-find-functions #'my/project-projectile t))
#+end_src

** Remote (TRAMP) save performance

Saving a file over TRAMP turns local filesystem calls into shell commands
run inside the remote host or container. Emacs is single-threaded and
blocks until they return, so every extra call is a visible UI freeze on
=C-x C-s=. These settings cut the per-save round-trips.

#+begin_src emacs-lisp
;; VC probes every backend in `vc-handled-backends' to work out which one
;; owns the file. Locally that is 8 cheap stats; over TRAMP it is 8 remote
;; commands. Cost of skipping: no git state in the mode line for remote files.
(with-eval-after-load 'tramp
  (setq vc-ignore-dir-regexp
        (format "\\(%s\\)\\|\\(%s\\)"
                vc-ignore-dir-regexp tramp-file-name-regexp)))

;; `backup-directory-alist' above matches ".*", so a remote file's backup is
;; copied across the link to this machine, and `version-control' makes that a
;; fresh numbered copy on every save. Skip backups for remote files only.
(defun my/backup-enable-predicate (name)
  "Disable backups for remote files; use the default rules otherwise."
  (and (not (file-remote-p name))
       (normal-backup-enable-predicate name)))
(setq backup-enable-predicate #'my/backup-enable-predicate)

;; Seconds a cached remote file attribute stays valid (default 10). projectile,
;; flycheck and lsp stat constantly. Tradeoff: files changed inside the
;; container by another process show up late. Lower to 30 if building in there.
(setq remote-file-name-inhibit-cache 60)

;; Seconds TRAMP waits on a connection before giving up (default 60). This
;; number is the freeze length when the remote end is wedged.
(setq tramp-connection-timeout 10)
#+end_src

** Remote (TRAMP) debugging

=tramp-verbose= is 3 by default, which logs errors, warnings, and the
connection buffers. Level 6 adds every string sent to and received from the
remote end, so a freeze shows up as the last command TRAMP was waiting on.

The cost is real: TRAMP formats every one of those messages whether or not
anyone reads them, so level 6 adds latency and a growing log file to exactly
the operations the section above is tuned to keep fast. It is on permanently
anyway, because a freeze you cannot reproduce on demand is the case opt-in
logging always misses. The toggle below drops back to 3 if it bites.

=tramp-debug-to-file= mirrors each =*debug tramp/...*= buffer to a file of the
same name in =tramp-compat-temporary-file-directory=, which resolves to
=~/.cache/emacs/= rather than =temporary-file-directory= whenever
=$XDG_CACHE_HOME= (or its =~/.cache= default) is writable. Buffers die with the
process, so the file is what survives a force quit, which is the reason to
bother.

Connections are cached, so the toggle flushes them: without that you keep the
existing session and never see the handshake where hangs usually happen.

#+begin_src emacs-lisp
;; On by default. A freeze that only happens occasionally is exactly the case
;; opt-in logging misses, so pay the overhead all the time and always have the
;; trail. Drop back to 3 with the toggle below if it ever becomes the problem.
(setq tramp-verbose 6
      tramp-debug-to-file t)

(defun my/tramp-debug-toggle ()
  "Toggle verbose TRAMP logging to debug buffers and to disk.
Closes cached connections so the next one is logged from the handshake up.
Open remote buffers reconnect on their next access."
  (interactive)
  (require 'tramp)
  (setq tramp-verbose (if (> tramp-verbose 3) 3 6)
        tramp-debug-to-file (> tramp-verbose 3))
  (tramp-cleanup-all-connections)
  (message "TRAMP verbose %d, file logging %s (%s)"
           tramp-verbose
           (if tramp-debug-to-file "on" "off")
           temporary-file-directory))
#+end_src

** Signature help

Signature help is the "what arguments does this function take" popup. It has
two halves, and only one of them is automatic:

- *Automatic* activation runs off =post-self-insert-hook=, so it fires only at
  the instant you *type* a trigger character (clangd advertises =( ) { } < > ,=).
  Putting point back inside a call you already wrote never triggers it.
- *Manual* activation via =lsp-signature-activate= works anywhere. lsp-mode
  binds it to =C-S-SPC=, which macOS tends to swallow for input-source
  switching, so bind a chord that actually survives.

The default display, =lsp-lv-message=, draws a one-line window at the very
bottom edge of the frame, far from where you are looking. =posframe= puts the
same text in a child frame at point instead.

#+begin_src emacs-lisp
(use-package posframe)

(with-eval-after-load 'lsp-mode
  ;; Child frames only exist on a graphical display; keep the bottom-line
  ;; renderer as the fallback so a terminal frame still shows something.
  (when (and (display-graphic-p) (require 'posframe nil t))
    (setq lsp-signature-function #'lsp-signature-posframe))

  ;; Stock params pin the frame to a fixed 10 lines. With documentation
  ;; rendering off the signature is a single line, so let it fit its content.
  (setq lsp-signature-posframe-params
        (list :poshandler #'posframe-poshandler-point-bottom-left-corner-upward
              :height nil :min-height 1 :max-height 6
              :width  nil :min-width 40 :max-width 100
              :border-width 1))

  (define-key lsp-mode-map (kbd "C-c s") #'lsp-signature-activate))
#+end_src

*** ESP-IDF project detection

Detect if we're in an ESP-IDF project (presence of =sdkconfig=) or a
PlatformIO ESP project (presence of =platformio.ini=), and point
clangd at the Xtensa / RISC-V cross-compilers.

#+begin_src emacs-lisp
(defun my/esp-project-p ()
  "Return non-nil if the current buffer is inside an ESP-IDF or PlatformIO ESP project."
  (or (locate-dominating-file
       (or buffer-file-name default-directory)
       "sdkconfig")
      (locate-dominating-file
       (or buffer-file-name default-directory)
       "platformio.ini")))

(defun my/c-mode-setup ()
  ;; Apple's /usr/bin/clangd has no Xtensa backend, so ESP32 headers get
  ;; parsed as arm64 Mach-O and every IRAM_ATTR/DRAM_ATTR errors out.
  ;; Espressif's clang build knows xtensa-esp32-elf. Only applied inside
  ;; ESP-IDF projects (sdkconfig present) or PlatformIO ESP projects
  ;; (platformio.ini present) so normal C/C++ still use plain clangd
  ;; from PATH.
  (when (my/esp-project-p)
    (setq-local lsp-clients-clangd-executable
                (expand-file-name
                 "~/.espressif/tools/esp-clang/esp-20.1.1_20250829/esp-clang/bin/clangd"))
    (setq-local lsp-clients-clangd-args
                (append lsp-clients-clangd-args
                        '("--query-driver=/Users/seijisato/.platformio/packages/**/bin/*-elf-*")))))

(add-hook 'c-mode-common-hook #'my/c-mode-setup)
#+end_src

** C#

*** Brace auto-formatting

Smart =({= and =})= insertion that opens a properly indented block,
but inserts a literal brace when typed inside a string.

#+begin_src emacs-lisp
(defun inside-quotes-question ()
  (nth 3 (syntax-ppss)))

(defun my-csharp-open-brace ()
  (interactive)
  (if (or (inside-quotes-question)
          (eq (char-before) ?\s))
      (insert "{")
    (progn
      (newline)
      (insert "{")
      (indent-according-to-mode)
      (newline)
      (indent-according-to-mode))))

(defun my-csharp-close-brace ()
  (interactive)
  (if (or (inside-quotes-question)
          (and (not (memq (char-before) '(?\s ?\t)))
               (save-excursion
                 (search-backward "{" nil t))))
      (insert "}")
    (progn
      (newline)
      (insert "}")
      (indent-according-to-mode)
      (previous-line)
      (indent-according-to-mode))))

(add-hook 'csharp-mode-hook
          (lambda ()

*** Live preview via impatient-mode + pandoc

Spin up a tiny HTTP server and pipe the buffer through pandoc with
MathJax support, so editing the file refreshes the preview live.

The preview renders in an =xwidget-webkit= buffer inside Emacs rather
than an external browser tab. xwidget embeds a real WebKit view, so
JavaScript runs and MathJax actually typesets the maths (=eww= would
not, it executes no JS). Falls back to `browse-url' on builds without
xwidget support.

#+begin_src emacs-lisp
(use-package simple-httpd)
(use-package impatient-mode)

(defun my-filter (buffer)
  (let (html source-text)
    (with-current-buffer buffer
      (setq source-text
            (buffer-substring-no-properties (point-min) (point-max))))
    (setq html
          (with-temp-buffer
            (insert source-text)
            (call-process-region
             (point-min) (point-max)
             "pandoc"
             t t nil
             "-f" "markdown+tex_math_dollars"
             "-t" "html5"
             "--standalone"
             "--mathjax")
            (buffer-string)))
    (princ html)))

(defun my/imp-live-url ()
  "URL that impatient-mode serves the current buffer at."
  (format "http://localhost:%d/imp/live/%s/"
          httpd-port (url-hexify-string (buffer-name))))

(defun my/imp-preview-in-emacs ()
  "Show this buffer's impatient preview in an xwidget beside it.
Falls back to the external browser on builds without xwidget support."
  (interactive)
  (let ((url (my/imp-live-url))
        (source (current-buffer)))
    (if (not (featurep 'xwidget-internal))
        (browse-url url)
      (xwidget-webkit-browse-url url)
      ;; `xwidget-webkit-goto-url' ends in `switch-to-buffer', which would
      ;; replace the file we are editing. Put the source buffer back, then
      ;; display the preview in a side window instead.
      (let ((preview (current-buffer)))
        (switch-to-buffer source)
        (display-buffer preview
                        '(display-buffer-in-side-window
                          (side . right)
                          (window-width . 0.5)))))))

(defun impatient-markdown ()
  (unless (process-status "httpd")
    (httpd-start))
  (impatient-mode 1)
  (imp-set-user-filter #'my-filter)
  (my/imp-preview-in-emacs))

(add-hook 'markdown-mode-hook #'impatient-markdown)
#+end_src

*** Scrolling the impatient preview with normal keys

=impatient-mode= does not serve the rendered markdown directly. It serves
a shim page (its own =index.html=) whose entire body is an
=<iframe id="content">= pinned to =height: 100%=, and rewrites that
iframe's document on every refresh. So the *outer* document is exactly
one viewport tall and has no overflow.

The stock =xwidget-webkit-scroll-*= commands scroll by injecting
=window.scrollBy(0, N)=, which targets that outer document, so on this
page they are silent no-ops: the key is bound, the command runs, the
JavaScript executes, nothing moves. (The mouse wheel still works, because
WebKit routes the event to the iframe under the pointer.)

These replacements aim the same JavaScript at the iframe's window,
falling back to the outer window on pages that have no such iframe, so
they stay correct for ordinary browsing too.

#+begin_src emacs-lisp
(defun my/xwidget-scroll-js (expr)
  "Run EXPR with `w' bound to the scrollable window of the current page.
That is the #content iframe on an impatient-mode preview, else the outer
window.  The iframe is same-origin with the shim, so reaching into its
contentWindow is permitted."
  (xwidget-webkit-execute-script
   (xwidget-webkit-current-session)
   (format "(function(){var f=document.getElementById('content');
var w=(f&&f.contentWindow)?f.contentWindow:window;%s})();" expr)))

(defun my/xwidget-scroll-up (&optional n)
  "Scroll preview up by N pixels, or one windowful."
  (interactive "P" xwidget-webkit-mode)
  (my/xwidget-scroll-js
   (format "w.scrollBy(0,%d);"
           (if n (prefix-numeric-value n)
             (xwidget-window-inside-pixel-height (selected-window))))))

(defun my/xwidget-scroll-down (&optional n)
  "Scroll preview down by N pixels, or one windowful."
  (interactive "P" xwidget-webkit-mode)
  (my/xwidget-scroll-js
   (format "w.scrollBy(0,-%d);"
           (if n (prefix-numeric-value n)
             (xwidget-window-inside-pixel-height (selected-window))))))

(defun my/xwidget-scroll-up-line (&optional n)
  "Scroll preview up by N lines."
  (interactive "p" xwidget-webkit-mode)
  (my/xwidget-scroll-up (* (or n 1) (window-font-height))))

(defun my/xwidget-scroll-down-line (&optional n)
  "Scroll preview down by N lines."
  (interactive "p" xwidget-webkit-mode)
  (my/xwidget-scroll-down (* (or n 1) (window-font-height))))

(defun my/xwidget-scroll-top ()
  "Scroll preview to the top."
  (interactive nil xwidget-webkit-mode)
  (my/xwidget-scroll-js "w.scrollTo(0,0);"))

(defun my/xwidget-scroll-bottom ()
  "Scroll preview to the bottom."
  (interactive nil xwidget-webkit-mode)
  (my/xwidget-scroll-js "w.scrollTo(0,w.document.body.scrollHeight);"))

;; `xwidget-webkit-mode-map' scrolls purely by command remapping, so these
;; override the stock remaps.  `scroll-up-line' / `scroll-down-line' are not
;; in the stock table at all, hence C-. and C-, needing their own entries.
(with-eval-after-load 'xwidget
  (define-key xwidget-webkit-mode-map [remap next-line]           #'my/xwidget-scroll-up-line)
  (define-key xwidget-webkit-mode-map [remap previous-line]       #'my/xwidget-scroll-down-line)
  (define-key xwidget-webkit-mode-map [remap scroll-up-command]   #'my/xwidget-scroll-up)
  (define-key xwidget-webkit-mode-map [remap scroll-down-command] #'my/xwidget-scroll-down)
  (define-key xwidget-webkit-mode-map [remap scroll-up-line]      #'my/xwidget-scroll-up-line)
  (define-key xwidget-webkit-mode-map [remap scroll-down-line]    #'my/xwidget-scroll-down-line)
  (define-key xwidget-webkit-mode-map [remap beginning-of-buffer] #'my/xwidget-scroll-top)
  (define-key xwidget-webkit-mode-map [remap end-of-buffer]       #'my/xwidget-scroll-bottom)
  (define-key xwidget-webkit-mode-map (kbd "SPC") #'my/xwidget-scroll-up)
  (define-key xwidget-webkit-mode-map (kbd "DEL") #'my/xwidget-scroll-down))
#+end_src

  ;; `set-process-window-size'.  libvterm and the PTY then disagree, and the

  ;; transcript every time the minibuffer grows.  The upstream bug it guards
  ;; against (anthropics/claude-code#1422) was closed 2025-08-22 against CLI
  ;; 1.0.6; we are far past that.

  ;; `json-rpc-error' but never calls `define-error' for that symbol.  A symbol
  ;; with no `error-conditions' is not a subtype of `error', so the
  ;; `condition-case' in `--handle-post' cannot catch it; the signal escapes the
  ;; web-server process filter and Emacs reports it at top level as
  ;;   error in process filter: peculiar error: -32601, "Method not found"
  ;; Defining the symbol lets the existing handler catch it and reply with a
  ;; proper JSON-RPC error object instead of crashing the filter.
  (define-error 'json-rpc-error "JSON-RPC error" 'error)

  ;; prompts falls through to the "Method not found" branch.  Answer both with
  ;; empty collections -- the sibling websocket server in claude-code-ide-mcp.el

  (advice-add 'claude-code-ide-mcp-http-server--dispatch :around
              (lambda (orig method params)
                (pcase method
                  ("resources/list" '((resources . [])))
                  ("resources/templates/list" '((resourceTemplates . [])))
                  ("prompts/list" '((prompts . [])))
